# PCB optimization working agreement

- Work from this repository root. Before **each** Python, pytest or router invocation, load `source scripts/env.sh`. Managed child Python processes must use the same wrapper.
- Read `docs/optimization-workflow.zh-CN.md` before changing solver algorithms. Start by inspecting `python -m scripts.optimize_pcb status` (after sourcing the environment) and the latest candidate's `result.json`; choose a concrete, general hypothesis tied to measured failures.
- Derive algorithms only from the blind specification's topology, pad geometry, pin attributes and electrical/mechanical requirements. Never add a project-specific reference designator, net name or human placement coordinate as an algorithm condition.
- Case 1–5 are exposed regression data. Never claim a new generalization score from them. Keep new holdouts sealed; the daily optimizer must not open reference PCBs or use sealed cases for tuning. A new blind evaluation needs a separate freeze/unseal experiment.
- Keep historical frozen boards and reports unchanged. Use `scripts.optimize_pcb` for daily experiments; the legacy v3 runner writes fixed output directories and must not be used to overwrite retained evidence.
- Finish source/test/config edits before starting a round. Do not edit executable source or pinned inputs while that round runs. Documentation-only edits may continue. Source drift invalidates the round; do not suppress that check.
- For meaningful solver changes, add independent tests and run a complete optimization round with a specific `--hypothesis`. A selected-case screening run is diagnostic only and cannot promote the baseline. Repeating identical source/inputs/settings to select a lucky result is prohibited.
- Experimental behavior should stay behind a uniform variant until qualified. A rejected candidate must not silently replace stable default behavior. Never use per-case variant selection.
- Baseline eligibility, existing hard gates, and full engineering acceptance are different facts. Preserve raw violations, incomplete connections, unknown current ratings and unverified mechanical dimensions. Do not weaken checks or turn unknown evidence into PASS.
- Record the concrete outcome, test count/time, regressions and remaining tasks in the round report. When a candidate regresses any board, retain the previous baseline and use the evidence to choose the next general improvement.
- For an independent external model reference, the user selected Google `gemini-4-hydrogen`. Use `scripts.run_gemini_reference` with a runtime credential file or `GEMINI_API_KEY`; never commit or print credentials, and never silently substitute another model. Send only anonymous blind input, not solver code/outputs or human reference boards. Preserve service errors and invalid outputs. A placement proposal is not a routed PCB or an engineering PASS.
