## 从冻结到比较

入库由隔离角色提取板框、纯机械孔、标准连接器库中临板边的接口、局部焊盘与网表。求解输入的板坐标重定位到局部原点，源仓库地址与提交字段为空。提取器重新移动及旋转其余器件，并删掉走线、过孔和覆铜，再验证投影完全一致。源项目及参考板保存在项目外部的保管区；评估运行不接收该路径。约束和隔离基于可审计流程和哈希承诺，同一工作区所有者仍有文件系统权限。参考身份和来源在完整冻结后发布。

```bash
source scripts/env.sh
python -m scripts.run_holdout run \
  --cohort benchmark_case/holdouts/diverse-four-layer-01.json \
  --directory artifacts/holdouts/diverse-four-layer-01 \
  --variant direct-repair
```

整组使用同一变体。每板保存原始路由器日志、独立审计、最终板、Gerber 与 3D 截图。登记、脱敏输入、源码归档和所有产物写入冻结清单。电气门禁失败仍可保留真实产物，进程失败或证据不全会使整组保持未解封状态。

`compare` 子命令要求登记路径、已完成轮次目录、独立记录的 `--freeze-sha256`、保管区 `--vault` 和新的 `--output`。它先复核整组源码、输入、文件集合和产物哈希，再校验所有参考的原始摘要与脱敏投影，最后生成相对指标和对照图。原始参考留在保管区。旧格式源若需要规范化，公开来源记录会注明工具版本与原件哈希。新批次的结果与推进优化的基线分别登记。

## 后续修复顺序

1. Case 10 的真实短路先出现在预布扇出，路由前 GND 铜已覆盖另一个物理回流网的焊盘。扇出必须围绕一个确切的网表网络身份工作，把其他回流域当作异网铜。应单独测试 SMD、带热焊盘的 IC 与同封装通孔网组，保持 DRC 和分层 LVS 不变。
2. Freerouting 对元件、连字符和焊盘分别做词法扫描。带标点的标识需要只影响导出端的可逆编码，实际网络名称和 SES 对应关系不变。应以含带连字符、括号及空格的合成板验证实际 JVM 导入和连接。
3. 部分不规则焊盘在 DSN 中外包成矩形，可能引入不真实的几何阻挡。需要按真实方位导出保守形状，并核对路由器最终使用的 45° 外包络与实际铜包络。独立测量和引擎报告均应保留。
4. 紧凑布局要用分侧元件占用，以及分别检查实际外壳和铜距的合法性。双面布局必须检查通孔对正反面两种摆放顺序的影响。Case 6 的空间碎片还需要有上限的局部重排，Case 7 和 9 需要先解决几何约束模型上的限制。
5. Case 3 的已知回归开路仍需联合规划相邻逃线。局部补通一条而把开路转移到另一条的试验保留为失败。Case 2 的明确器件型号可用厂家封装和天线图纸补足几何证据；一般元件的未知高度继续计为未知。

旧报告的 `unrouted_nets` 字段实际直接记录 fastroute 的未完成连接数。路由器同时报告网络数，二者不能相减来解读已闭合网络。此处以原始连接数和独立 LVS 开路网络分列。
